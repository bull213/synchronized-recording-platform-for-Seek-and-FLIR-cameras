# Recorder layout

Start the editable recorder with `Start_Sync_Recorder.cmd`. Existing recording
modes, acquisition settings, calibration profiles, output formats, and external
trigger commands are retained. The cage ROI tool uses its original interface.

## Everyday recording

1. Choose the recording mode in the top bar. The device list distinguishes
   connected devices from those selected for recording.
2. Set the session label and recording folder under **Session**. In microphone
   modes, choose an input under **Devices** and use **Connect & monitor**.
3. Read the banner beside the recording controls. It explains missing devices,
   pending recovery, file finalization, and invalid after-shutter settings.
   **Show settings** opens the relevant section; it does not change settings.
4. Click **Record**. **Stop**, elapsed time, recording state, and trigger arming
   remain visible while switching pages or enlarging a camera.
5. Wait for **Saved**, **Saved with gaps**, or **Failed** after stopping.
   **Open recording folder** opens the run directory for all recording modes.
   Audible MP3 conversion has a separate completion/failure message.

## Settings and views

- Expand **Seek settings** for sampling rate, shutter, calibration, palette,
  pipeline, and sharpening. After-shutter sampling requires an applied Custom
  shutter configuration. Changing the dropdown alone does not apply it.
- Expand **Audio settings** for microphone metadata, pre-trigger duration, and
  audible MP3 options. Inactive settings retain their values across mode changes.
- **Show live audio** places the existing spectrogram below the cameras. Drag
  the horizontal divider to resize it. **Live audio** provides the full FFT,
  frequency, history, floor, freeze, and zoom controls for the same plot.
- **Review audio** retains WAV loading, time-window selection, spectrogram
  inspection, and audible MP3 export. **Triggers** retains TCP and TTL settings.
- **View** includes diagnostics, Seek-section visibility, last-session export,
  MP3 playback, and **Reset layout**. Resetting the layout does not reset recording
  settings, output paths, labels, or calibration.
- **Hide settings**, **Preview mode**, draggable camera dividers, and camera
  enlargement remain available. Escape restores the preceding view.
- Warnings remain visible when settings and diagnostics are hidden. Dismissing
  a notification clears its banner, not the log or the underlying problem.

Short windows use one row of cameras when sufficient width is available and
move synchronization details into the result tooltip. Settings and oversized
views remain scrollable. Status is conveyed in text as well as color.

  with Python 3.12.10, using the existing development environment.
- Synthetic recording self-test: **passed** (segmented Seek/FLIR video, thermal
  CSV, PCM WAV, timing reports, and MP3 export).
- Source inventory: **99 reviewed files**; manifest validation passed.
- New coverage checks readiness explanations, advanced controls, retained values,
  live audio docking during recording, saved results, and persistent errors.
- Existing camera-mode, laptop-geometry, audio, and ROI GUI checks pass.
- Actual demo screenshots are generated by `scripts/capture_recorder_redesign.py`
  under `.validation/recorder-redesign`. Separate processes with
  `QT_SCALE_FACTOR=1.25` and `1.5` exercise actual Qt display scaling.

The two skips cover POSIX serial integration and independent MP3 decoding when
FFmpeg is unavailable. The public repository retains its corrected recording
fixtures and segmented-output self-test. Physical device acquisition and a new
Windows executable build were not performed for this redesign.
